Privacy Policy

Last updated: 23 September 2026. SyncNet does not request or store private keys or seed phrases. Wallet connection and transaction approval are handled by the wallet provider selected in your browser.

SyncNet uses browser storage for local features such as launch records (MY LAUNCHES: prepared/sent launches, transaction hashes, intent records and signatures), Duel records and short-lived upload sessions (never keys). Clearing browser storage removes those local records.

Simulation and chain checks use RPC and PAR/indexer requests. Project names, tickers, descriptions, wallet addresses and calldata used in simulation may therefore be visible to the RPC/indexer/hosting providers involved even before a real transaction is sent.

When you choose to upload a project image, it is sent through a server-side pinning function to the configured IPFS provider. IPFS publication is public and effectively permanent. The server decodes every image and re-encodes it (PNG or GIF) before pinning, which removes embedded metadata such as EXIF/GPS, comments and XMP.

SyncNet does not currently use a public account system and does not automatically post to social networks on your behalf. When public uploads are open, you sign a free wallet message (no transaction) so uploads can be tied to your wallet for rate limits. Server logs record hashed identifiers (IP address, wallet address) and error details for abuse prevention; rate-limit counters expire automatically. If you publish a launch proof to the SyncNet Registry, the proof (deployer address, token, transaction hash, intent record and signature) becomes public. Project Marketplace records (operator claims, listings, offers, operator transfers and deal settlement checklists) are stored server-side and include wallet addresses, the signed terms and the signatures themselves; listings are public, and operator history is kept permanently in the Project Passport. Third parties involved: the Robinhood Chain RPC (chain reads and simulations), the PAR indexer and token list (api.par.family, par.family), IPFS gateways used to check and display images (gateway.pinata.cloud, ipfs.io, dweb.link), the pinning providers used for uploads (Pinata and, if configured, a second pinning service), the key-value store used for rate limits, Registry records and Marketplace records (Upstash), the hosting provider (Netlify) and your wallet provider.

Browser storage and simulations

SyncNet uses browser storage for local UI state such as Duel records and local launch/recovery records; Marketplace records live server-side, not in your browser. Operator-only test credentials may be kept in session storage for the current tab. Launch simulation sends the project metadata and prepared call to a public Robinhood Chain RPC using eth_call; do not treat simulated metadata as secret.
